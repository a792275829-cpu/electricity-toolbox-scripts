# 桌面启动故障与源码冲突恢复

## 已确认的故障（2026-11-02）

0.1.26 启动时，`prepare_workspace.py` 报出“检测到本地源码修改”，冲突文件为 `电力工具箱/toolbox/` 下的 `power_benefit_page.py`、`spot_price_page.py` 和 `widgets.py`。备份内容均与 Git 提交 `0088e0e` 完全一致，与当前发行源码不同。证据支持正式版托管目录混入了开发代码，但不能据此确定具体写入者或复制操作。

启动初始化比较目标文件、上次安装清单和当前发行清单。文件既不符合原记录，也不符合当前发行内容时，保护逻辑停止覆盖。业务后台和原生界面因此未启动，外壳显示启动故障窗口。该保护避免丢失本地修改，应继续保留。

本次将三个冲突文件备份后，用已安装发行包的初始化流程恢复源码；初始化退出码为 0，发行清单中的 674 个文件摘要全部一致，重启后后台、原生界面及主窗口正常。仅验证启动恢复，未执行真实取数、写入或上传。

## 当前人工恢复流程

1. 记录第一条有效异常、退出码、复现命令、版本、发行 build、冲突相对路径和原安装清单；诊断材料仅保存在本机，避免包含账号或登录资料。
2. 确认故障实例没有正在运行的业务任务，再退出对应实例；不得强制终止写入或上传进程。
3. 将冲突文件按原相对路径复制到用户目录 `backups/startup-repair-时间戳/`，同时保存原安装清单；逐文件校验备份摘要与原文件一致。备份失败时停止恢复。
4. 仅移走已验证备份的冲突源码，然后使用已安装发行包的内置 Python 和 `payload/bootstrap/prepare_workspace.py`，以 `--managed` 模式初始化同一用户目录。禁止删除整个 `app/`，禁止清空 `data/`、`samples/`、独立 profile 或锁目录，禁止改动已签名 `.app` 内的资源。

6. 实际重启已安装应用，确认业务后台、原生界面和主窗口正常，检查是否仍有启动异常。记录备份位置、校验数量和未验证的业务流程。
