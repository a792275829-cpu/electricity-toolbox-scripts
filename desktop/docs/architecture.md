# 三层架构与原界面兼容

主界面直接复用原 Tk 页面及弹窗，不进行网页重绘。页面布局、主题、字段、日期控件、文件选择、右侧任务／账号／诊断和日志控件继续由原代码维护。

```text
原 Tk 界面（native_bridge.py、toolbox/ui_tasks.py）
        ↕ 界面生命周期与业务 RPC
Rust/Tauri（src-tauri/src/main.rs）
        ↕ JSON-lines，协议版本 3
Python 服务（service_bridge.py、toolbox/service.py）
        ↕ 原任务引擎、按需工作进程
原业务脚本 / Python 模块 / 必需的 Node 工具与独立浏览器
```

## 职责

- 界面层：收集表单值、保留原有验证提示和确认弹窗、展示任务、保存界面配置。`RemoteTaskRegistry` 在主线程读取 Tk 变量，把普通参数发送给服务；原业务闭包不在界面线程执行。本地任务记录用于驱动原控件，执行与结果由服务决定。
- 应用管理层：单实例、托盘、窗口唤起、启动环境、进程生命周期及界面与业务服务间的请求转发。只有界面进程拥有可见应用身份；外壳在 Info.plist 中声明 `LSUIElement`，在启动完成时再次应用后台激活策略。
- 业务层：白名单工具／操作、参数校验、任务并发、取消、结果、日志和下载。复用原解析、计算、登录、Excel 写入、报告及上传代码；`commands.py` 同时供旧页面与服务构造命令。

WPS 保留原文档／区域编辑器；在线文档读取、预览、浏览器操作和写入经服务执行，写入完成仍回读比较。更新窗口也复用原版，通过 `remote_updater.py` 将检查和 DMG 下载交给业务服务。

## 协议与任务

界面 RPC 经过 Rust 转发，前后两端各自关联请求编号。界面启动先核对业务协议版本。服务只接受已注册工具和参数，拒绝任意命令、未知字段与操作。

`start` 需要唯一请求标识。同一标识和参数返回已有任务；不同参数复用标识会报错。界面保留响应不确定时的请求标识，避免连接超时后重复写入或上传。业务失败不自动重跑，日志保留业务 traceback 和退出码，并使用原有脱敏规则。

服务事件队列和回看日志各最多保留 2,000 项，单条回传日志限制长度；事件游标标明被截断的历史。界面仅在任务执行或检查更新期间轮询服务。原日志控件及右侧任务列表保持原交互。

每个任务在受管理的工作进程中调用原业务脚本。取消沿工作进程组终止其子进程；不可安全中断的写入仍拒绝取消。Node 仅在需要的上传操作中解析和启动。各工具继续使用自己的登录态、profile 和锁。

## 退出与数据

正常退出先走原界面关闭流程：运行任务确认、不可中断写入保护、账号保存。界面结束后 Rust 请求服务退出，最后退出外壳。界面意外退出时也不直接杀死业务服务；服务等待不可中断任务完成。后台异常不会自动重启或重放写入。

源码、用户数据和初始样例仍沿用现有目录与迁移逻辑。工作进程请求文件位于系统临时目录，使用私有权限，在成功、失败和取消后删除。版本与发行规则继续只使用 DMG 和 `.dmg.sha256`，不恢复旧签名压缩包更新通道。

空闲时有三个基础进程。此改动的目标是界面不被业务阻塞、依赖与故障隔离、统一管理；不以进程数量作为性能指标，也不承诺未经发行构建测量的内存或启动改善。

## 验证与回退

- `desktop/tests/python/test_service.py`：无 Tk 服务启动、真实工作进程、请求去重、退出保护、取消、日志边界与参数契约。
- `desktop/tests/python/test_ui_layers.py`：原控件树／几何位置对比、原按钮经业务服务执行任务。
- `desktop/tests/python/ui_smoke_entry.py`：调试构建专用入口。通过 `TOOLBOX_UI_TEST_ENTRY` 指定；只在 debug 构建生效，正式版忽略该变量。使用临时目录中的样本副本验证实际 Tk → Rust → Python 链路和退出。
- 原工具箱测试逐模块在独立 Python 进程运行，避免大型 Tk 套件在同一进程积累事件循环状态；初始化 `PYTHONPATH` 为仓库根目录。

`00_启动/电力工具箱.command` 继续使用原 TaskRegistry 与原页面执行方式，可作为源码回退入口。桌面三层入口为 `00_启动/Tauri开发版.command`。真实登录、远程上传、跨 Mac 安装及 DMG 升级需要另行按实际环境验收，不能用本地样本测试替代。
